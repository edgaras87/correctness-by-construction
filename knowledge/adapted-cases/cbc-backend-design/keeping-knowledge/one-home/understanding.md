This text says why one home reaches this repo's agent as an Agent Rule loaded in every session. Each Defined Term here is defined in the Backend Kit's Defined Terms.

## 1. Why every session

A fact is retold in whatever text is being written: a record, a comment, a line of configuration. So the rule binds whenever any text is written, which is every task. The record being written has its Record Stub, but that Record Stub says nothing of the record the fact was taken from. So at the moment the rule is needed, no Record Stub that holds it is open.

The rule was written from the start, in the Maintainer Repo's manual on records, and one repo of this kind still told one Plan Step's story in four records (one home, in CBC backend design, kept in the Maintainer Repo, §2, *What the work showed*). A rule kept where it is not read at the moment does not bind. So it reaches the agent through the Ambient Channel: an Agent Rule loaded in every session.

## 2. Why no paths

The rule carries no `paths:` list. A Paths Rule loads only when a file under its paths is touched with the agent's tools, and an edit made by script loads nothing (the Claude Code Tool Binding's understanding, §6, *Paths Rules*). A fact can be retold in any file, so no list of paths covers the moment.
