# Briefing — inventory reservation, correctness-first

## The situation

A portfolio of correctness demonstrations is being built — each
project one claim proven under one adversity class, the claim
stated in writing and the path from claim to proof followable. The
piece wanted now: inventory reservation under contention — the
canonical correctness adversity — built end to end the
correctness-first way: promise first, system derived from it,
evidence that stages the adversity for real.

This is a CbC project: the method arrived at birth, pinned, and is
followed as shipped.

## The audience

The portfolio reader — a party judging whether the author can do
correctness-driven backend construction. The claim is sold to this
reader; consumers of the running system only generate adversity
and enter later as environment actors in the system definition.
Everything downstream is bound by legibility to this reader.

## The territory

Inventory reservation, spun off from checkout-system's territory —
its inventory-reservation line, unbuilt there. Thematic lineage,
not decomposition: whatever promise is chosen stands on its own
feet and owes nothing to checkout-system's structure, and nothing
of checkout-system is needed here — this briefing carries all the
territory says. Two costs come with it, accepted knowingly: the
tiling debt (no guaranteed clean re-composition into
checkout-system) and the exclusion of between-areas composition
adversities (checkout-system's own difficulty).

## The bar a promise must clear

The promise is not chosen yet. Whatever sentence is chosen must
pass all of these:

1. One claim, one sentence — a timeless state property the system
   below it can be derived from.
2. It names its adversity class in the sentence.
3. It could trivially be false — naive implementations actually
   break it; the negation is a concrete observable event.
4. The negation can be staged — the adversity created for real,
   the witness read from persisted state, checkable from outside.
5. Proving it matters to the audience — contention, legibly.
6. Narrow enough for one project — one owner, a full lifecycle
   inside one system's walls.

## The open decision

Which single sentence, in this territory, under contention. That
choice creates the project: the sentence lands in the intent, and
the name follows from it. Working name: safe-reservations; the
naming decision confirms or overturns it.
